PHASE 6A V2 — Free Public Level Tests, Random Question Bank, Audio Bank, and Owner Control

Goal:
Build a complete free public Arabic level testing system for Habiba Nabil Arabic Academy.

Important:
This phase is completely separate from the paid post-payment level check.
Do not require payment.
Do not create a paid student account automatically.
Do not create a lesson package.
Do not mark anything as paid.
Do not confuse this with the paid onboarding level check after checkout.

This phase is for:
- Free public lead generation
- Existing student placement/replacement testing
- Quick preliminary level checking
- Full free Arabic placement testing
- Conversion to booking/payment
- Owner/Teacher manual review and follow-up

Current project note:
The app is currently using PostgreSQL in Replit.
Keep the current PostgreSQL setup.
Do not migrate the database in this phase.
Do not change the payment/onboarding flow from Phase 4/5.

There are two free test types:

1. Quick Arabic Level Check
2. Full Free Arabic Placement Test

This version must use:
- Question bank
- Random test generation
- Anti-repeat logic
- Owner/Teacher full control
- Audio file management

- Speaking prompt management

PART 4 — RANDOMIZATION REQUIREMENT
==================================================

The test must not show the exact same questions every time.

Build a random test generator that selects questions from the database question bank.

Important behavior:
- Every test attempt should generate a fixed snapshot of selected questions.
- Once an attempt starts, questions must not change on page refresh.
- Refresh must reload the same attempt snapshot, not regenerate questions.
- A new attempt should try to avoid repeating the same questions for the same student/device/IP.
- Do not rely only on IP because IP can change or be shared.

Use a combination of:
- existingStudentId if logged in
- WhatsApp number for new applicant
- deviceId cookie
- ipHash
- userAgentHash if practical
- previous attempt history

Privacy:
- Do not store raw IP if avoidable.
- Store ipHash instead.
- Do not expose device/IP data to public users.

Anti-repeat logic:
- Track which questions/audio/reading texts were shown in previous attempts.
- Prefer unseen questions for the same person/device.
- If not enough unseen questions exist, allow repeats but distribute fairly.
- Owner can configure anti-repeat window in days.

Important:
Refresh must never change the current attempt questions.
